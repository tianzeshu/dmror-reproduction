# 交付完整性检查

公开 Git 仓库未包含历史 `results/` 和 `logs/`。请下载 [v1.0.0 Release](https://github.com/tianzeshu/dmror-reproduction/releases/tag/v1.0.0) 的完整公开工程，在解压目录执行本检查。验收只读取冻结 NPZ、metadata、源码和数值实验输出，不需要省略的新闻原文。

从工程根目录执行：

```text
python scripts/verify_delivery.py --frozen-source provenance/frozen_training_source/dmror --output reports/delivery_validation.json
```

默认是严格检查，全部 260 个正式任务、52 个数据集/模式组合的五种子结果，以及本地文档链接齐备后才通过。检查器只读取数据和实验输出，不重训，不加载 checkpoint 的 pickle 对象；可选 `--output` 写出完整 JSON 检查记录。

检查内容包括：协议的四个数据集、13 个模式及固定五个种子；数据文件 SHA-256 与 metadata、各轮 config/result 记录一致；运行配置符合冻结协议；权重 ZIP 结构与 CRC、scaler、连续训练历史、原始预测和日志齐全；预测索引、日期与标签对应输入，概率/强度有限且范围合法；指标分母与已知标签一致。从冻结指标例程和保存的验证预测重算节点 Macro-F1/边正类 F1 阈值，核对验证与测试使用相同值，不用测试标签选阈值。ICKG-Weak 的边真值必须全部未知，路径指标必须为 NA。所有正式运行的实现哈希清单必须一致，并与指定的冻结源文件对应。

另检查完整模型的 16 轮验证搜索与三个基线的 48 轮验证搜索，以及各数据集/模式是否获得相同四组配置预算。赢家由保存的**验证** AUPRC 重算，平局优先较小隐藏宽度和学习率；候选表、冻结赢家及正式配置继承关系必须一致。重算选择不读取测试指标。完整性检查不证明执行者从未查看测试数据；实际选参程序和数据流仍需结合代码审计解释。

历史限制：最早的完整模型 16 轮 `validation_search` 运行发生在实现摘要记录加入之前，其原始 config 没有 `implementation_sha256`。检查器只对这一明确阶段允许该字段缺失，逐项检查其实际配置、数据、预测、历史和权重，并在 JSON 的 `unfingerprinted_early_validation_runs` 及 warnings 中保留全部名称。没有追补或虚构源代码摘要，因此不能声称这 16 轮源码可由保存的哈希追溯。后续 48 轮基线验证搜索及 260 轮正式实验仍必须提供实现摘要；正式实验的摘要必须统一且与源文件对应。

训练后新增、未列入冻结清单的模块会明确记录为补充模块，不会称作正式训练所用代码。若确实需要修改已有文件，应另外保留训练时源文件，并使用 `--frozen-source` 指向该快照，同时说明修改原因；不能通过忽略摘要差异来掩盖执行版本漂移。

本交付的冻结快照保存在 `provenance/frozen_training_source/dmror/`，从未覆盖的服务器源码导出。当前工程仅 `apply_cache.py` 在正式实验开始后增加跨平台 NPZ ZIP 元数据规范化；训练不调用此工具，模型、训练、损失、指标及其余已记录源码均与冻结版本一致。最新缓存工具应保留用于精确复建，不能替换实验 config 中的原哈希。上方最终命令显式使用冻结快照验证历史执行版本；不指定 `--frozen-source` 时默认对比当前 `dmror/`，因此该已披露差异仍会被报告。

在训练尚未结束或结果尚未下载齐时，可临时使用 `--allow-incomplete`。缺失内容会记为 pending，已有内容的数据错配、非有限值及运行失败仍会失败。`status=incomplete` 不能当作最终验收通过；最终交付记录应使用默认严格命令生成。

README 与 docs 中的 Markdown 本地文件链接会检查是否存在；页内锚点和外部网站不检查。实际图形排版仍需打开 PNG/SVG/PDF 进行视觉核验，依赖环境仍需安装后运行测试。该检查不判断弱标签事实真伪、真实因果传播或原稿实验结论是否成立。
